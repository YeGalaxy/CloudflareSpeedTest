# CloudflareSpeedTest 项目结构

## 项目概述

**CloudflareSpeedTest** 是一个用 Go 语言编写的 Cloudflare CDN 速度测试工具。它可以测试 Cloudflare CDN（或其他 CDN）的各个 IP 地址的延迟和下载速度，帮助用户找到最快的 IP。

- **项目语言**: Go 1.24+
- **主要功能**: TCP 延迟测速、HTTP 延迟测速、下载速度测试、结果上报、定时任务、Docker 容器化
- **输出格式**: CSV 文件
- **模块路径**: `github.com/XIU2/CloudflareSpeedTest`
- **项目版本**: v2.3.4

## 核心文件详解

### main.go - 项目入口

- **功能**: 命令行参数解析、程序流程控制
- **职责**:
  - 解析用户输入的命令行参数（延迟测速线程数、次数、下载测速配置等）
  - 调用 task 模块进行测试
  - 输出测试结果到 CSV 文件（延迟测速结果和完整测速结果分别输出）
  - 调用 utils 模块中的 report 功能上报结果（可选）
  - 调用 utils 模块中的 scheduler 功能管理定时任务（可选）
- **核心函数**:

| 函数 | 说明 |
|------|------|
| `main()` | 主流程：延迟测速 → 导出延迟CSV → 过滤 → 下载测速 → 导出完整CSV → 打印结果 → 上报（可选） |
| `handleReport()` | 处理测速后上报逻辑（支持多目标逗号分隔） |
| `handleReportOnly()` | 仅上报模式，跳过测速直接上报已有结果 |
| `buildReportConfig()` | 构建上报配置对象 |
| `derivePingOutput()` | 根据输出文件名推导延迟测速结果文件名 |
| `handleSchedulerList()` | 列出定时任务 |
| `handleSchedulerDelete()` | 删除定时任务 |
| `handleSchedulerCron()` | 通过 cron 表达式创建定时任务 |
| `handleSchedulerInteractive()` | 交互式定时任务管理 |
| `buildCurrentArgs()` | 构建当前命令行参数列表（用于定时任务） |
| `checkUpdate()` | 检查版本更新 |

- **支持的参数分组**:

| 分组 | 参数 | 说明 |
|------|------|------|
| 测速参数 | `-n`, `-t`, `-dn`, `-dt`, `-tp`, `-url` | 延迟/下载测速配置 |
| 过滤参数 | `-tl`, `-tll`, `-tlr`, `-sl` | 延迟/速度/丢包率过滤 |
| 输出参数 | `-p`, `-f`, `-ip`, `-o`, `-dd`, `-allip` | 结果输出和IP段配置 |
| 上报参数 | `-report`, `-report-only`, `-report-file`, `-report-port` 等 | 结果上报配置 |
| 定时参数 | `-scheduler`, `-scheduler-list`, `-scheduler-delete`, `-scheduler-cron` 等 | 定时任务管理 |
| 其他参数 | `-v`, `-h`, `-debug` | 版本、帮助、调试模式 |

### ip.txt & ipv6.txt - 测试数据

- **功能**: 存储 Cloudflare 的 IP 地址段
- **格式**: 每行一个 IP 或 IP 段（CIDR 格式），支持指定端口和标签
- **用途**: 程序从这些文件读取需要测试的 IP
- **行格式**: `IP或CIDR[:端口] [#标签]`
  - `1.0.0.1` — 单个 IP，使用默认端口
  - `1.0.0.1:8443` — 单个 IP，指定端口 8443
  - `1.0.0.0/24` — IP 段，使用默认端口
  - `1.0.0.0/24:2053` — IP 段，指定端口 2053
  - `1.0.0.1:443 #HKG` — 指定端口和标签
  - `[2606:4700::1]:443` — IPv6 指定端口

### airport_codes.json - 机场代码映射

- **功能**: 存储 IATA 机场代码到地区名称的映射关系
- **用途**: 在 HTTPing 模式下识别 Cloudflare 地区代码对应的实际地区
- **结构**: JSON 格式，包含机场代码、中文名称、地区和国家信息
- **嵌入方式**: 使用 Go `//go:embed` 编译时嵌入到二进制文件

- **功能**: 提供 Docker 环境变量的配置模板
- **用途**: 用户复制为 `.env` 文件并填写实际值，用于 Docker Compose 部署
- **配置项**:

| `REMOTE_HOST` | 远程服务器 IP 地址 | 服务器IP地址 |
| `REMOTE_PORT` | 远程服务器 SSH 端口 | 22 |
| `REMOTE_USER` | 远程服务器用户名 | 服务器用户名 |

## task 模块 - 核心测速功能

### ip.go - IP 地址处理

- **功能**: IP 地址段解析、随机 IP 生成、多端口和标签支持
- **核心数据结构**:

| 类型 | 说明 |
|------|------|
| `IPEntry` | IP 条目结构体，包含 `IP`（*net.IPAddr）、`Port`（int）、`Tag`（string） |
| `IPRanges` | IP 范围管理，用于 CIDR 解析和 IP 生成 |

- **IPEntry.GetPort()**: 如果条目指定了端口则使用指定端口，否则回退到全局 `-tp` 参数
- **多端口支持**: 每个 IP 条目拥有独立端口，支持以下两种模式：
  - **一个 IP 多端口**: 同一 IP 出现多次，每次指定不同端口（如 `1.2.3.4:443`、`1.2.3.4:8443`）
  - **一个 IP 一个端口**: 不同 IP 各自指定端口（如 `1.2.3.1:443`、`1.2.3.2:8443`）
  - 两种模式可混合使用

- **主要接口**:

| 函数/变量 | 类型 | 说明 |
|-----------|------|------|
| `InitRandSeed()` | 函数 | 初始化随机数种子 |
| `IPFile` | 变量 (string) | IP 段数据文件路径，默认 `ip.txt`，支持本地文件和远程 URL |
| `IPText` | 变量 (string) | 直接指定的 IP 段数据（逗号分隔） |
| `TestAll` | 变量 (bool) | 是否测速全部 IP，默认 false |
| `Routines` | 变量 (int) | 并发测速线程数，默认 200 |
| `PingTimes` | 变量 (int) | 单个 IP 测速次数，默认 4 |
| `TCPPort` | 变量 (int) | 全局默认测速端口，默认 443 |
| `URL` | 变量 (string) | 测速地址，默认 `https://cf.xiu2.xyz/url` |
| `Timeout` | 变量 (time.Duration) | 下载测速超时时间 |
| `parseIPLine(line)` | 函数 | 解析单行 IP 数据，提取 IP 部分、端口和标签 |
| `loadIPRanges()` | 函数 | 加载 IP 范围数据，返回 `[]IPEntry` |

### ipfile.go - IP 数据文件加载

- **功能**: 从本地文件或远程 URL 加载 IP 数据，支持多种文件格式
- **支持的文件格式**:

| 格式 | 检测方式 | 说明 |
|------|----------|------|
| TXT | 文件扩展名或默认 | 每行一个 IP/CIDR，支持 `IP:端口 #标签` 格式 |
| CSV | 文件扩展名或内容检测 | 表头自动识别 IP/端口/标签列，无表头时按顺序解析 |
| JSON | 文件扩展名或内容检测 | 支持字符串数组 `["1.0.0.1:443"]` 或对象数组 `[{"ip":"1.0.0.1","port":443,"tag":"HKG"}]` |

- **远程文件支持**: `-f` 参数支持 HTTP/HTTPS URL，自动下载远程 IP 数据文件
- **核心接口**:

| 函数 | 说明 |
|------|------|
| `LoadIPFile(path)` | 加载 IP 文件（自动检测格式），返回解析后的行列表 |
| `fetchRemoteFile(url)` | 从远程 URL 下载文件内容 |
| `readLocalFile(path)` | 读取本地文件（自动回退 data/ 目录） |
| `detectFileType(path, content)` | 自动检测文件类型（TXT/CSV/JSON） |
| `parseTXT(content)` | 解析 TXT 格式 |
| `parseCSV(content)` | 解析 CSV 格式（自动识别表头列名） |
| `parseJSON(content)` | 解析 JSON 格式（字符串数组或对象数组） |

### tcping.go - TCP 延迟测速

- **功能**: 通过 TCP 连接测试延迟
- **机制**:
  - 创建与目标 IP 指定端口的 TCP 连接
  - 测量连接建立时间（RTT）
  - 多次测试求平均延迟
  - 使用 `IPEntry` 的 `GetPort()` 获取每个条目的端口
- **核心接口**:

| 函数/类型 | 说明 |
|-----------|------|
| `Ping` | 延迟测速结构体 |
| `NewPing()` | 创建 Ping 实例（加载 IP 数据） |
| `(*Ping).Run()` | 执行延迟测速，返回 `PingDelaySet` |
| `(*Ping).checkConnection(entry)` | 检测连接（根据模式选择 TCP/HTTP） |
| `(*Ping).tcpingHandler(entry)` | 处理单个 IP 条目的延迟测速 |
| `(*Ping).tcping(ip, port)` | TCP 连接测速，返回是否成功和延迟 |

### httping.go - HTTP 延迟测速

- **功能**: 通过 HTTP 请求测试延迟
- **机制**:
  - 发送 HTTP HEAD 请求到指定 URL
  - 通过 `getDialContext(entry)` 强制连接到指定 IP 和端口
  - 测量 HTTP 响应时间
  - 支持指定有效的 HTTP 状态码
  - 支持从响应头提取地区码（Cloudflare/CDN77/Bunny/AWS CloudFront/Fastly/Gcore）
- **核心变量**:

| 变量 | 类型 | 说明 |
|------|------|------|
| `Httping` | bool | 是否启用 HTTPing 模式 |
| `HttpingStatusCode` | int | 有效 HTTP 状态码（0 表示使用默认 200/301/302） |
| `HttpingCFColo` | string | Cloudflare 地区码过滤 |
| `HttpingCFColomap` | *sync.Map | 地区码映射表 |
| `MapColoMap()` | 函数 | 加载机场代码映射 |
| `getHeaderColo(header)` | 函数 | 从 HTTP 响应头提取地区码（支持多种 CDN） |
| `getDialContext(entry)` | 函数 | 创建指定 IP+端口的拨号上下文 |

### download.go - 下载速度测试

- **功能**: 测试从指定 IP 的实际下载速度
- **机制**:
  - 使用 `getDialContext(entry)` 强制连接到指定 IP 和端口
  - 使用指数加权移动平均（EWMA）计算下载速度
  - 支持按地区分配下载测速名额（`-cfcolo` 模式下每个地区独立选取）
- **核心接口**:

| 函数/变量 | 说明 |
|-----------|------|
| `TestDownloadSpeed(data)` | 对延迟测速结果进行下载测速 |
| `downloadHandler(entry)` | 单个 IP 下载测速处理 |
| `getDialContext(entry)` | 创建指定 IP+端口的拨号上下文（HTTP 请求用） |
| `MinSpeed` | 下载速度下限（MB/s） |
| `TestCount` | 下载测速 IP 数量 |
| `Disable` | 是否禁用下载测速 |

- **地区分配逻辑**（`-cfcolo` 模式）:
  - 按地区分组延迟测速结果
  - 每个指定地区独立排序，选取最低延迟的 IP
  - 每个地区最多选取 `TestCount` 个 IP 进行下载测速

## utils 模块 - 工具函数

### csv.go - 结果输出

- **功能**: 将测试结果导出为 CSV 文件
- **CSV 列定义**（完整测速结果，12 列）:

| 列序 | 列名 | 说明 |
|------|------|------|
| 1 | IP 地址 | 测速 IP |
| 2 | 端口 | 测速端口 |
| 3 | 已发送 | 发送的数据包数 |
| 4 | 已接收 | 接收的数据包数 |
| 5 | 丢包率 | 丢包百分比 |
| 6 | 平均延迟 | 平均延迟（ms） |
| 7 | 下载速度(MB/s) | 下载速度 |
| 8 | 地区码 | IATA 机场码或 CDN 地区码 |
| 9 | 地区码名称 | 地区码对应的中文名称 |
| 10 | 二字地区码 | 国家/地区二字码 |
| 11 | 二字地区名称 | 国家/地区名称 |
| 12 | 标签 | IP 条目标签 |

- **延迟测速结果**（11 列，不含下载速度列）

- **核心数据结构**:

| 类型 | 说明 |
|------|------|
| `PingData` | 延迟测速数据（IP、端口、标签、发送/接收数、延迟、地区码） |
| `CloudflareIPData` | 完整测速数据（嵌入 PingData + 下载速度） |
| `PingDelaySet` | 延迟测速结果集（按丢包率+延迟排序） |
| `DownloadSpeedSet` | 下载测速结果集（按下载速度降序排序） |

- **核心接口**:

| 函数/变量 | 类型 | 说明 |
|-----------|------|------|
| `ExportCsv(data)` | 函数 | 导出完整测速结果到 CSV 文件（12 列） |
| `ExportPingCsv(data, output)` | 函数 | 导出延迟测速结果到 CSV 文件（11 列） |
| `Output` | 变量 (string) | 输出文件名，默认 `result.csv` |
| `InputMaxDelay` | 变量 (Duration) | 延迟上限，默认 9999ms |
| `InputMinDelay` | 变量 (Duration) | 延迟下限，默认 0ms |
| `InputMaxLossRate` | 变量 (float32) | 丢包率上限，默认 1.0 |
| `PrintNum` | 变量 (int) | 输出结果数量 |
| `NoPrintResult()` | 函数 | 判断是否不打印结果 |
| `Debug` | 变量 (bool) | 调试模式 |
| `LoadAirportCodes()` | 函数 | 加载机场代码映射（嵌入数据） |
| `GetAirportCodeName(colo)` | 函数 | 获取机场码对应名称 |
| `GetAirportCountryCode(colo)` | 函数 | 获取国家二字码 |
| `GetAirportCountryName(colo)` | 函数 | 获取国家名称 |

### report.go - 结果上报功能

- **核心数据结构**:

| 类型 | 说明 |

| `PreferredIP` | 优选 IP 数据（IP、端口、名称） |
| `CloudflareIPResult` | CSV 解析后的测速结果（含地区码、国家码等） |
| `GitHubContentResponse` | GitHub API 响应（文件 SHA） |

- **核心接口**:

| 函数 | 说明 |
|------|------|
| `ReportResults(resultFile, cfg, target, port)` | 上报入口函数，根据 target 分发到不同上报方式 |
| `UploadToCloudflareAPI(cfg, results, port)` | 上传到 Cloudflare Workers API |
| `UploadToGitHub(cfg, results, port)` | 上传到 GitHub 仓库 |
| `ReadResultCSV(filePath)` | 读取并解析 CSV 结果文件（兼容不同列数） |
| `FormatPreferredIPs(results, port)` | 格式化为 Workers API 数据格式 |
| `FormatGitHubContent(results, port)` | 格式化为 GitHub 文件内容格式（`IP:端口#国家码-地区-速度`） |
| `LoadConfig(path)` | 加载上报配置文件 |
| `SaveConfig(path, cfg)` | 保存上报配置文件 |

- **上报流程**:

```
读取 result.csv → 解析 CSV 数据 → 根据 reportTarget 选择上报方式
  ├─ cloudflare → 检查配置 → GET 检查现有IP → DELETE 清除旧数据 → POST 上传新数据
  └─ github → 检查配置 → GET 检查文件是否存在 → PUT 创建/更新文件
```

- **重试机制**:
  - 最大重试次数：3 次
  - 重试间隔：2 秒
  - 仅对服务端错误（HTTP 5xx）和网络错误进行重试
  - 客户端错误（HTTP 4xx）直接返回

- **配置持久化**: 配置文件默认路径 `.cfst_config.json`，优先级为命令行参数 > 配置文件
- **多目标上报**: `-report` 参数支持逗号分隔多个上报目标（如 `cloudflare,github`）

## 工作流程

### 完整测速流程

```
1. 读取 IP 数据文件（本地/远程，TXT/CSV/JSON 格式）
   ↓
2. 解析 IP 地址段，生成 IPEntry 列表（含端口和标签）
   ↓
3. TCP/HTTP 延迟测速（可并发，默认 200 线程，每个条目使用各自端口）
   ↓
4. 导出延迟测速结果到 CSV 文件
   ↓
5. 根据延迟和丢包率过滤结果
   ↓
6. 对最优 IP 进行下载速度测试（支持按地区分配名额）
   ↓
7. 结果汇总、排序
   ↓
8. 导出完整测速结果 CSV 文件
   ↓
9. 打印测速结果
   ↓
10. （可选）上报结果到 Cloudflare Workers API 或 GitHub（支持多目标）
   ↓
11. （可选）运行 script/ 中的脚本自动应用优选 IP
```

### 仅上报流程

```
1. 读取已有的 result.csv 文件
   ↓
2. 解析 CSV 数据（兼容不同列数格式）
   ↓
3. 根据 -report 参数选择上报方式（支持逗号分隔多目标）
   ↓
4. 上报到 Cloudflare Workers API 或 GitHub
```

### 定时任务流程

```
1. 用户通过 -scheduler 参数交互式创建任务
   ↓
2. 根据操作系统选择任务创建方式
   ↓
3. Linux/macOS: 写入 crontab（带 # CloudflareSpeedTest 标记）
   ↓
4. Windows: 创建 schtasks 计划任务
   ↓
5. 任务按计划自动执行测速
```

### Docker 定时任务流程

```
1. 通过 CFST_CRON 环境变量指定 cron 表达式
   ↓
2. entrypoint.sh 创建测速脚本 run_cfst.sh
   ↓
3. 写入 crontab 并持久化到 /app/data/crontab
   ↓
4. 启动 crond 服务
   ↓
5. （可选）CFST_CRON_ONCE=true 先执行一次
   ↓
6. （可选）CFST_MIHOMO_CONTAINER 指定 mihomo 容器，测速前停止、测速后启动
   ↓
7. 后台循环每 5 分钟保存 crontab
   ↓
8. tail -f /dev/null 保持容器运行
```

## IP 数据文件格式详解

### TXT 格式

```
# 注释行以 # 开头
1.0.0.1
1.0.0.1:8443
1.0.0.0/24
1.0.0.0/24:2053
1.0.0.1:443 #HKG
[2606:4700::1]:443
2606:4700::/32
```

### CSV 格式

```csv
IP 地址,端口,标签
1.0.0.1,443,HKG
1.0.0.2,8443,NRT
1.0.0.3,,SJC
```

或无表头（自动按 IP,端口,标签 顺序解析）。

### JSON 格式

字符串数组：
```json
["1.0.0.1:443", "1.0.0.2:8443 #NRT"]
```

对象数组：
```json
[
  {"ip": "1.0.0.1", "port": 443, "tag": "HKG"},
  {"ip": "1.0.0.2", "port": 8443, "tag": "NRT"}
]
```

## 项目特点

- **高效并发**: 支持最多 1000 个并发线程测速
- **多种测速模式**: TCP 和 HTTP 两种延迟测速方式
- **多端口支持**: 每个 IP 条目可独立指定端口，支持一个 IP 多端口和混合模式
- **灵活过滤**: 支持按延迟、丢包率等条件过滤结果
- **多格式输入**: 支持 TXT/CSV/JSON 格式的 IP 数据文件，支持本地和远程 URL
- **结果上报**: 支持 Cloudflare Workers API 和 GitHub 两种上报方式，支持多目标同时上报
- **仅上报模式**: 无需重新测速即可直接上报已有结果
- **定时任务**: 跨平台定时任务管理（crontab/schtasks）
- **Docker 支持**: 完整的容器化部署方案，支持多架构
- **mihomo 集成**: Docker 模式下支持测速前停止 mihomo、测速后自动启动
- **自动化支持**: 提供脚本快速应用优选 IP 到系统
- **跨平台**: 支持 Windows、Linux、macOS
- **轻量级**: 单一二进制文件，无其他依赖
- **机场代码映射**: 内置机场代码数据库，增强地区识别
- **地区分配**: `-cfcolo` 模式下按地区独立分配下载测速名额

## 基本使用

```bash
# 编译项目
go build

# 基本测速（默认配置）
./cfst

# 自定义配置
./cfst -n 200 -t 4 -dn 10 -dt 10 -tp 443

# 使用 HTTP 模式
./cfst -httping -url "https://cf.xiu2.xyz/url"

# 指定 Cloudflare 地区
./cfst -cfcolo HKG,SGP,NRT

# 使用含端口和标签的 IP 数据文件
./cfst -f ip_with_ports.txt

# 使用远程 IP 数据文件
./cfst -f "https://example.com/ip.txt"

# 使用 CSV 格式的 IP 数据文件
./cfst -f ip_data.csv

# 测速并上报到 Cloudflare Workers API
./cfst -report cloudflare -report-worker-domain example.com -report-uuid your-uuid

# 测速并上报到 GitHub
./cfst -report github -report-github-token ghp_xxxx -report-github-owner username -report-github-repo repo

# 同时上报到多个目标
./cfst -report cloudflare,github -report-worker-domain example.com -report-uuid your-uuid -report-github-token ghp_xxxx -report-github-owner username -report-github-repo repo

# 仅上报已有结果（无需重新测速）
./cfst -report-only -report cloudflare -report-file result.csv -report-worker-domain example.com -report-uuid your-uuid

# 创建定时任务
./cfst -scheduler

# 通过 cron 表达式直接创建定时任务
./cfst -scheduler-cron "0 2 * * *" -scheduler-task-name cfst_daily

# 列出定时任务
./cfst -scheduler-list

# 删除定时任务
./cfst -scheduler-delete task_name

# Docker 运行
docker compose up

# Docker 定时任务模式（通过环境变量）
docker run -e CFST_CRON="0 2 * * *" cfst:latest

# Docker 带 mihomo 集成
docker run -v /var/run/docker.sock:/var/run/docker.sock -e CFST_MIHOMO_CONTAINER=mihomo cfst:latest
```
