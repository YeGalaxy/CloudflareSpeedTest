# CloudflareSpeedTest 重构文档说明

## 1. 重构背景

CloudflareSpeedTest 原项目（XIU2/CloudflareSpeedTest）是一个用于测试 Cloudflare CDN 所有 IP 的延迟和速度的工具。原项目功能完善，但在实际使用场景中存在以下不足：

- **缺少结果上报机制**：测速结果仅保存在本地 CSV 文件中，无法自动同步到远程服务，不便于多节点部署场景下的结果集中管理。
- **缺少定时任务支持**：用户需要手动执行测速或依赖外部定时工具（如 crontab、Windows 任务计划程序），缺乏统一的任务管理界面。
- **缺少容器化支持**：原项目未提供 Docker 部署方案，在云服务器、NAS 等环境下的部署不够便捷。
- **缺少开发工具配置**：原项目缺少现代开发工具配置，如 VS Code 调试配置。

基于参考项目 `byJoey/yx-tools` 的功能实现，对 CloudflareSpeedTest 进行了功能扩展与集成重构，同时优化了项目结构和开发体验。

## 2. 重构目标

| 目标 | 说明 |
|------|------|
| 结果上报 | 实现完整的结果数据收集、格式化处理及上报机制，支持 Cloudflare Workers API 和 GitHub 两种上报方式 |
| 定时任务 | 开发跨平台的定时任务管理系统，支持任务创建、编辑、删除及状态管理 |
| Docker 支持 | 添加完整的 Docker 容器化支持，包括 Dockerfile、docker-compose 配置及多架构构建 |
| 开发体验优化 | 添加 VS Code 调试配置，提升开发效率 |
| 向后兼容 | 所有新增功能均为可选配置，不影响原有功能的正常使用 |
| 代码质量 | 遵循原项目代码风格，确保代码可维护性 |

**核心数据结构**：

```go
// 上报配置
type Config struct {

    UUID         string `json:"uuid"`
    GitHubToken  string `json:"github_token"`
    GitHubOwner  string `json:"github_owner"`

```

- 仅对服务端错误（HTTP 5xx）和网络错误进行重试
- 客户端错误（HTTP 4xx）直接返回，不重试

## 4. 技术实现细节

### 4.1 结果上报实现

#### Cloudflare Workers API 上报

1. **API 路径**：`/{uuid}/api/preferred-ips`
2. **上报流程**：
   - `GET` 请求检查现有 IP 数据
   - `DELETE` 请求清除所有现有数据（`{"all": true}`）
   - `POST` 请求上传新的优选 IP 列表
3. **数据格式**：
   ```json
   [
     {"ip": "1.2.3.4", "port": 443, "name": "HKG-5.23MB/s"},
     {"ip": "5.6.7.8", "port": 443, "name": "NRT-3.45MB/s"}
   ]
   ```

#### GitHub 上报

1. **API 路径**：`https://api.github.com/repos/{owner}/{repo}/contents/{path}`
2. **上报流程**：
   - `GET` 请求检查文件是否已存在（获取 SHA）
   - 如果文件存在：`PUT` 请求更新文件（携带 SHA）
   - 如果文件不存在：`PUT` 请求创建文件
3. **文件内容格式**：
   ```
   1.2.3.4:443#HKG-5.23MB/s
   5.6.7.8:443#NRT-3.45MB/s
   ```
4. **认证方式**：GitHub Personal Access Token（需要 `repo` 权限）

#### 配置持久化

配置文件默认路径为 `.cloudflare_speedtest_config.json`，优先级为：
1. 命令行参数
2. 配置文件中的值（仅当命令行参数为空时使用）

### 4.2 定时任务实现

#### Linux/macOS（crontab）

- 使用 `crontab -l` 读取现有 crontab
- 使用 `crontab -` 写入新的 crontab
- 任务标记：每行末尾添加 `# CloudflareSpeedTest` 注释
- 替换逻辑：按任务名称匹配并替换已有任务

#### Windows（schtasks）

- 任务名称前缀：`cfst_`
- 支持的调度类型：
  - 每天（`/sc daily /st HH:MM`）
  - 每小时（`/sc hourly /mo 1`）
  - 每周（`/sc weekly /d DAY /st HH:MM`）
- 使用 `/f` 参数强制覆盖已有任务

### 4.3 Docker 容器化实现

#### 多架构构建

通过 `TARGETARCH` 构建参数实现：
- `amd64`：x86_64 架构（主流服务器/PC）
- `arm64`：ARM64 架构（树莓派/M1 Mac/云服务器）

#### 安全优化

- 创建专用用户 `cfst` 和组，避免以 root 身份运行
- 设置适当的文件权限
- 配置时区为 Asia/Shanghai
- 添加必要的系统工具包

#### 数据持久化

- 数据目录：`/app/data`
- 通过 Docker 卷实现数据持久化
- 自动复制默认配置文件到数据目录

### 4.4 机场代码数据库集成

#### 数据来源

- 基于 IATA 机场代码标准

## 7. 不填写上报目标信息的影响说明

### 7.1 系统行为

当不填写上报目标信息（`-report` 参数为空或 `CFST_REPORT` 环境变量为空）时：

- **主流程不受影响**：测速正常执行，结果正常保存到 CSV 文件，正常打印到控制台
- **上报模块不执行**：`handleReport()` 函数不会被调用，上报相关代码完全不运行
- **无错误信息**：不会产生任何警告或错误
- **无数据丢失**：所有测速结果仍然完整保存在本地 CSV 文件中

### 7.2 代码逻辑

```go
// main.go 第 230-232 行
if reportTarget != "" {
    handleReport()
}
```

当 `reportTarget` 为空字符串时，条件判断为 false，`handleReport()` 被跳过。

### 7.3 最佳实践建议

1. **单机使用场景**：不需要上报，测速结果保存在本地即可
2. **多节点管理场景**：建议配置 Cloudflare Workers API 上报，便于集中管理各节点测速结果
3. **版本控制场景**：建议配置 GitHub 上报，测速结果自动提交到仓库，便于追踪历史变化
4. **配置持久化**：首次配置后，参数会保存到 `.cloudflare_speedtest_config.json`，后续运行无需重复输入

## 8. 不设置定时任务的影响说明

### 8.1 系统行为

当不设置定时任务（不使用 `-scheduler*` 参数或 `CFST_CRON` 环境变量为空）时：

- **程序执行一次即退出**：测速完成后程序正常退出，无后台进程
- **无默认定时行为**：系统不会自动创建任何定时任务
- **无数据同步影响**：由于没有后台进程，不存在数据同步问题
- **Docker 容器行为**：容器执行一次测速后自动退出

### 8.2 代码逻辑

```go
// main.go 第 199-217 行
if schedulerList {
    handleSchedulerList()
    os.Exit(0)
}
if schedulerDelete != "" {
    handleSchedulerDelete()
    os.Exit(0)
}
if schedulerCron != "" {
    handleSchedulerCron()
    os.Exit(0)
}
if schedulerMode {
    handleSchedulerInteractive()
    os.Exit(0)
}
```

当所有 scheduler 相关参数均为默认值时，以上条件均不满足，调度器代码不执行。

### 8.3 替代方案

如果不使用内置定时任务功能，可以通过以下方式实现定时测速：

1. **Linux crontab**：手动编辑 crontab 配置定时执行
2. **Windows 任务计划程序**：手动创建计划任务
3. **Docker CFST_CRON**：在 Docker 环境中设置 `CFST_CRON` 环境变量
4. **外部调度系统**：使用 Jenkins、GitHub Actions 等外部工具调度

### 8.4 最佳实践建议

1. **偶尔测速**：不需要定时任务，手动执行即可
2. **定期监控**：建议使用 Docker + `CFST_CRON` 方式，简单可靠
3. **多任务管理**：建议使用内置 `-scheduler` 交互式管理，便于查看和修改
4. **生产环境**：建议配合上报功能使用，确保测速结果可追溯
